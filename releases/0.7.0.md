# Bukatoko 0.7.0

## Summary

Move the five primary screens into one HTML shell with animated internal navigation, preserving backend contracts and legacy entry links. Refine mobile category readability and navigation geometry.

## Changes

- Generate Home, Browse, Wanted, Sell and Account as inert templates in index.html and mount only the selected screen. Keep the header, session and theme across navigation; legacy entry points bootstrap the shell with existing parameters and fragments.
- Intercept primary links and search forms, support History Back/Forward, and animate screen changes and the active navigation indicator. Bound outgoing-animation waits so background tabs cannot stall navigation. Respect reduced motion and focus the new main content.
- Dispose page listeners/React list roots and gate old request continuations before mounting another screen. Preserve relative API/uploads, cookie sessions and CSRF. Confirm before leaving edited Sell/Wanted forms; checkpoint successful submissions before redirecting or resetting.
- Reduce mobile home category headings/labels, provide stable two-line label space, add 12px above Browse quick categories and use equal-height rounded-rectangle navigation items instead of oval selections.
- Include the router in Pages exports and require it in frontend-only packages. Document generated-template editing and add router/stale-response regression coverage.
- Inspect feat/bukatoko-0.2 before merging: its tip remains 09394bf and all commits are already contained in main via aa1ffd9. A normal merge reports Already up to date; no additional feature changes or merge commit are needed.

## Validation

- All 43 Node frontend/export/connection/router cases passed, including active-template isolation, query preservation, edited-form guards, legacy bootstrap, paused-animation fallback and stale-response suppression.
- Disposable backend suites passed 53 API smoke, 70 feature and 40 structural checks. All 22 repository/release helper unit tests passed, including the updated frontend package fixture.
- Authorized local backend browser checks completed login, persisted session across main-screen navigation, keyword search, POST wanted request, and POST listing followed by its detail page. No production credentials or data were used.
- Browser Back/Forward worked in the backend shell and in a static subfolder preview. The static preview opened a legacy route into the single shell and switched the five main screens. Mobile labels fit in ID/EN, Browse quick-category padding is 12px, navigation selections are 64px high with 16px corners, and sampled screens have no horizontal overflow. No application console errors appeared.
- Branch ancestry, staged metadata and overlap guards are checked before the authorized commit; GitHub Actions and release assets are verified after pushing.

## Known limits

- Listing detail, profile and moderation remain standalone pages. The four legacy entry HTML files remain as editable template sources and compatibility fallbacks; runtime navigation among the five main screens uses index.html.
- Back/Forward restores route/query, not prior scroll position. Edited form values are protected by a leave confirmation, not persisted across confirmed discards or reloads. Server writes already accepted are not undone by leaving a screen.
- Pages is still sample-data/read-only. Instabox deployment remains cancelled. No server code, hosted database or uploads were changed.
- Browser checks sample flows/devices rather than every integrated administrative action. No measured performance improvement or comprehensive security certification is claimed.
