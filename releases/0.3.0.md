# Bukatoko 0.3.0

## Summary

Extends the marketplace beyond listings: the wanted board now accepts offers from sellers, every listing and request carries public likes and comments, and accounts gained verification, notifications, deals with handover, review replies and moderator tooling. All of it runs on the same dependency-free Python server and SQLite file.

## Changes

- Social layer: one like per account per post, toggleable; public comment threads on listings and on wanted requests; reply counts and like counts served with every card.
- Wanted board responses: a seller picks one of their own active listings or writes a message, the requester receives a `wanted_reply` notification, and the reply list is public. Attaching somebody else's listing is rejected.
- Accounts: email verification codes, password reset, moderation freeze, and profile badges. Sessions stay HttpOnly cookies.
- Lifecycle: listing expiry with renew, sold/archived states, saved searches with new-match counts, and a notification feed with unread badge.
- Deals: accepted offers open a deal with a handover state machine, each participant confirms, and only participants may review.
- Reviews: rating summary with per-star distribution, sort control, and a single reply from the reviewed seller.
- Moderation: report queue, actions to dismiss, remove a listing or freeze an account, plus a dedicated moderator page.
- Search: autocomplete suggestions, photo-only filter, typo tolerance and URL-backed filters.
- Tooling: SQLite backup helper, 404 page, and a demo banner that states the data is sample data.

## Validation

- 50 API smoke checks, 70 feature/security/lifecycle checks and 40 page-structure checks passed against a temporary database (160 total, no failures).
- Four Pages export/adapter tests passed after allowlisting the two new pages.
- Browser click-through at 390 px: like toggles 0 to 1, comment posts and renders, wanted reply sends and notifies, account tabs switch, no horizontal overflow on any of the seven pages.
- Computed contrast passed in both themes on home, browse, listing and account pages; manual keyboard and screen-reader paths unchanged.

## Known limits

Password reset and verification codes are printed to the server log instead of email, because the demo has no mail service. Uploaded photos live on local disk. Data in the public Pages preview is read-only fixture data; likes, comments and replies need the Python server. The demo has no real payments.
