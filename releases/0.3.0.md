# Bukatoko 0.3.0

## Summary

Rebuild the marketplace interface around product browsing, consistent component spacing, light-default theming and an organized account workspace.

## Changes

- Replace the accumulated stylesheet with a single token-based component system and remove inline layout styles from all seven pages and JavaScript components.
- Add desktop sidebar filters, responsive product grids, clearer price/condition/location/seller hierarchy and clickable item photos.
- Choose square catalog images for varied product shapes and a 4:3 detail gallery; keep images uncropped with contain sizing. Account list thumbnails remain compact landscape images.
- Rebuild account summary, navigation and content columns; remove empty thumbnail columns from message/offer rows and align the information note with panel content.
- Default new visits to light mode while preserving explicit saved theme choices. Add short interaction transitions with reduced-motion support.
- Improve keyboard access to image enlargement and account tabs. Add UI regression tests to the Pages build.
- Record REA/external design references, the image-ratio decision and actual verification limits.

## Validation

- 39 API smoke checks passed on a disposable application/database copy during the rebuild, including listing, account, upload, offer, message, review and authorization flows.
- Seven Node test cases passed for public Pages export/adapter behavior, default theme and persistence, square cards, item links and sold/sample states.
- All seven HTML documents passed balanced-markup, unique-ID, relative-link and no-inline-style checks; 11 pages/assets were served successfully by Python.
- JavaScript syntax and Git whitespace checks passed. Remote-overlap checks found no incoming collaborator commits.

## Known limits

Browser access was previously denied for both local and public preview origins. Actual visual rendering, mobile layout, interaction click-through, console state and animation smoothness remain unverified; no visual or performance pass is claimed. The square-image choice is a design judgment, not an A/B result. GitHub Pages remains read-only; full account and transaction behavior requires the Python backend. Publication was explicitly requested with these verification limits recorded in docs/UI-REBUILD-REVIEW.md.
