# Bukatoko 0.8.0

## Summary

Add saved-item actions and comment counts to catalog cards, simplify detail actions, and provide consistent policy and support pages.

## Changes

- Hide the home wanted-summary panel on phones while retaining it on larger screens.
- Replace the wanted-response back-arrow appearance with a rounded discussion icon and explicit response label.
- Add catalog-card save controls using the existing authenticated saved API, synchronize confirmed state across duplicate cards, and link comment counts to expanded item discussions.
- Update comment totals only after a successful post, without replacing the total with the API's bounded comment-page length.
- Remove the seller-block control from item detail; retain sharing and item reporting as accessible icon-only controls aligned to the end of the seller panel.
- Use a shared three-column footer, bilingual terms/privacy pages, and a bug-report portal with local preview, GitHub issue handoff, and text download.
- Include all new support pages/assets in Pages exports and frontend release packages; add tests to the Pages workflow.
- Restore the missing recent-item storage key used by the existing recent-history helpers.

## Validation

- Local backend fixture: 53 API smoke, 70 feature and 43 page checks passed (166 total).
- Frontend/router/export suite: 47 tests passed, including new save, comment-total, report privacy and error-state cases.
- Repository workflow/package suite: 22 passed; the package test passed again after adding the support asset requirement.
- Browser: 390 x 844 home/catalog/detail/support/privacy and 1280 x 900 footer checked; no horizontal overflow in checked screens. ID/EN switching preserves the typed report. Card comment link opens the correct expanded detail discussion.
- Focused source review: report preview uses textContent, encoded values, a fixed GitHub destination, no automatic diagnostics submission, and a guarded long-URL fallback. Backend code and data are unchanged.

## Known limits

- GitHub Pages remains a read-only catalog; account writes require the existing same-origin Python host. Instabox deployment is not part of this release.
- Bug submission finishes on GitHub and may require a GitHub account; no new backend inbox is provided. Issues are public. Text download is available as an alternative.
- Maintainers have not configured a dedicated private privacy/security contact channel, production retention schedule, or self-service account deletion. The policy pages state these limits; operational facts and policies need review before a production launch.
