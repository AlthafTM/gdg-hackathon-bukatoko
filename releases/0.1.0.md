# Bukatoko 0.1.0

## Summary

The first working implementation of Bukatoko: a marketplace where one account can sell items and post wanted-item requests with a price range. It ships as a self-contained app in `app/`, with a static frontend and a dependency-free Python server backed by SQLite.

## Changes

- `app/server.py`: HTTP server, JSON API, SQLite schema (users, sessions, listings, photos, wanted, offers, messages, reviews, reports, blocks, saved, searches), seed data, photo upload, orphan cleanup, Open Graph rendering for `/p/<id>`.
- `app/assets/app.js` and `app/assets/styles.css`: frontend with account dialog, listing detail, gallery plus lightbox, chat, account tabs, skeleton/empty/error states, ID/EN toggle and light/dark theme.
- Pages: `index.html`, `jelajah.html`, `listing.html`, `jual.html`, `cari.html`, `akun.html`, `profil.html`.
- `app/README.md` documents the API surface, demo accounts, limits, and the honest list of what is not built.
- Root `README.md` gains an `app/` row in the repository map.
- Palette follow-up: primary `#7C3AED`, secondary `#A78BFA`, accent `#22C55E`, background `#FAF9FF`, and text `#1F1637`; shared semantic tokens cover all seven pages, dark mode, hover/focus, active navigation/tabs, forms, prices and notifications. Favicon, generated demo images and `app/DESIGN.md` use the same palette.
- Initialize the system theme on load and track system changes until a manual preference is saved. Uploaded product photos and marketplace/server behavior are preserved.

## Validation

- `python app/tests/api_smoke.py` against a fresh database: 38 checks passed, 0 failed. Covers signup/login, duplicate account rejection, upload authorization, listing creation, offer rules (self-offer, over-asking, duplicate open offer), seller-only acceptance, sold state, chat both directions, unread counts, review eligibility and duplicate review rejection, saved items, saved searches, reports, blocks, write authorization, and the Open Graph page.
- Browser walkthrough on 1440 px and 390 px viewports: no horizontal overflow on seven pages, listing created with two uploaded photos and served from `/uploads/`, offer accepted by the seller which marked the item sold, review published (rating shown as "4 dari 1 ulasan"), report and block submitted, lightbox opened, ID/EN toggle changed navigation labels.
- Public URL check from outside the machine: `/p/l1004` returned the expected `og:title`.

## Known limits

- Demo authentication only: no email verification, no password reset, no rate limiting on login.
- Reports are stored but there is no moderator interface or automated moderation.
- No payments, shipping, push or email notifications; EXIF metadata in uploaded photos is not stripped.
- UI flows were verified manually in a browser; only the API has an automated test.
- Images for seeded listings are generated placeholders, not real product photos.
- Palette review is prepared on a feature branch. The repository workflow currently runs on PRs targeting `main` and pushes to `main`; a PR targeting `feat/bukatoko-app` does not trigger it automatically. No release or deployment is performed by publishing this review branch.
