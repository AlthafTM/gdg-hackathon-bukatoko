# Bukatoko 0.6.5

## Summary

Remove preview messaging from the published interface and refine task-page navigation, account positioning and form spacing.

## Changes

- Remove any existing catalog search/category bars on Wanted, Sell and Account and add a page-scoped CSS guard. Keep catalog tools on Home and Browse. Add regression cases covering already-inserted bars as well as normal catalog pages.
- Vertically centre the guest account title, description and login action within the available main area while leaving authenticated account layout unchanged.
- Remove the requested publishing explanation from Sell. Share one form-footer layout between Sell and Wanted: 24px separation from fields, 16px between footer items and no extra required-note margins.
- Omit the Pages top strip/footer notices and hide the home preview statistics. Keep the existing live-app link in the footer when configured, and use a short unavailable-feature message without implementation instructions.
- Preserve sample fixtures, read-only write rejection, stock-photo labels and backend API/session behavior. Refresh HTML asset and adapter cache keys.

## Validation

- All 38 Node frontend, shell, locale, motion, React, wanted, location, public export and connection cases passed. The new shell cases verified removal of existing bars on all three task screens and retained Home/Browse tools.
- Disposable backend suites passed 53 API smoke, 70 feature and 40 UI checks. All 22 repository/release helper unit tests passed.
- Local exported-preview browser checks confirmed no search on Sell/Wanted, no Pages notices, centred account content, and matching 24px/16px form-footer spacing. Sampled mobile Sell/Wanted screens had no horizontal overflow and retained submission controls. No console errors appeared.
- Public file inspection before editing found v0.6.4 task HTML/JS already included the search guard and reported Cache-Control max-age=600. A stale browser response is a possible explanation, not a reproduced browser-specific cause.
- Staged metadata and overlap guards run before the authorized commit. GitHub Actions and release assets are verified after pushing.

## Known limits

- Pages still uses sample data and rejects writes. Removing explanatory banners does not connect it to a backend. The configured live-app link remains available.
- A client retaining older HTML can continue using old cache-keyed assets until it reloads. Backend deployment remains cancelled; no Instabox files, data or credentials changed.
