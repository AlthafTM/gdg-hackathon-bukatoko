# Bukatoko 0.5.1

## Summary

Unblock the Pages build after the 0.5.0 translation checks caught an inline-code false positive and a missing CORS error translation.

## Changes

- Exclude script/style raw-text blocks from the static visible-copy translation scan; keep scanning page text, placeholders and accessibility labels.
- Translate the CORS preflight rejection message into English.
- Preserve the 0.5.0 tag and release; publish this correction as a separate patch.

## Validation

- GitHub Actions for 0.5.0: repository checks and release publication passed; Pages build passed its exporter and 17 of 19 Node cases, then stopped before deployment on the two translation checks corrected here.
- Source syntax and staged whitespace/release metadata checked locally. Runtime tests are not rerun on this host because the installed security-audit execution sandbox is unavailable.
- The authorized push triggers the full configured workflows again; report their observed results separately rather than treating the source change as a passing runtime result.

## Known limits

- The remote backend still needs the updated code, environment configuration and restart described in docs/BACKEND-CONNECTION.md. Live CORS/session connectivity and visual browser behavior remain unverified.
- All other known limits from 0.5.0 remain, including the two unresolved backend security findings and third-party cookie restrictions.
